          Executors
          global — shared by every project
          
          
        

        

          An executor is where a harness actually runs. Host forks a child process of this
          server with its user, filesystem, and network — no isolation. Container runs
          the workload in a Docker/Podman sandbox on this machine. Remote dispatches it to an
          enrolled edge device that dialled out to this control plane. Bind a project to one from its Overview tab.
        


        

        


        
        

          
No executors yet

          

            Expected on a hardened hub: with executors.allow_host_process: false the built-in
            host driver is refused, so the first executor is one you add. Runs are refused until then.
          


          
1. Mint a single-use enrollment token on this hub:

          
cloop executor enroll --name edge-1


          
2. Run the printed command on the device. It dials
            outward, so the device needs no inbound port and may sit behind NAT:

          
cloop executor agent --bundle <bundle-from-step-1>


          

            
          


          

            A container or Kubernetes executor needs no enrollment — enable one under
            executors: in .cloop/config.yaml. Run cloop hub doctor
            to check the whole configuration, and see
            docs/architecture/executors.md
            for what each backend isolates.
          

        

        

      

    


    
    

      

        

          Quotas
          global — admin only
          
        

        

          Roles decide whether an identity may act; quotas decide how much. Each cell is the ceiling,
          with live usage below it. Leave a cell blank for unlimited — which is not
          the same as 0, meaning none allowed. Edits here override the policy in
          ui.quotas for that one identity and are recorded in the audit trail.
          Enforcement is at admission — before a run is dispatched, a project created, or an
          executor enrolled — so a client that skips this dashboard is refused just the same.
          The same counters are exported as Prometheus gauges on /metrics.
        


        

        


        

          

            
            
          

        

      

    


    
    

      

        

          Audit trail
          global — admin only
          
            checking…
          
          
          
          
        

        

          Append-only, hash-chained record of every state mutation: task changes, config writes,
          authorization decisions, credential leases, egress grants, and executor fleet changes.
          Each row's hash covers the one before it, so any edit, deletion, or insertion made behind
          cloop's back breaks the chain and is reported above. Export the same data with
          cloop audit-log export --format jsonl|csv|cef.

          Secrets & grants
          global — maintainer and above
          
          
          
        

        

          A secret is a sealed credential at rest. A grant says which executor or
          project may use one, under which allowlist, until when. A lease is what an executor is
          actually holding right now — minutes, not days — and is the only thing here that puts a
          credential on a disk. cloop never returns secret material through this panel: rows carry a fingerprint
          of the sealed record, never the value.

Live leases 

          

            Credentials materialised into a running workload's memory-backed directory. Revoking wipes that
            directory now and pushes a scrub to every executor already holding the credential, rather than
            waiting for the task to exit.
          

          

            What a scrub reaches: credential files are wiped and egress allowlist entries are
            dropped, so the next read or connection fails. An environment variable is dropped from the agent's
            memory, but a task that already has it in its own environment keeps it — no control plane can
            reach into another process. Use Revoke & kill when the credential itself is compromised.
            A lease held by an offline agent shows unreachable and is replayed when it reconnects.
          

          

            No leases outstanding. Nothing on this hub is holding a brokered credential.

New grant

    

      A grant is scoped in three dimensions: who (a project, an executor, or a label selector),
      what (the allowlist below, which differs per kind), and how long. There is
      no "allow everything" default — an empty allowlist is rejected rather than read as unrestricted.
    


    

      
      
    


    

      
      
      

    


    

      

        
        
        

          project:/srv/app, executor:edge-01, label:region=eu,gpu=true,
          or any. Matching is exact — no prefix fuzziness.
        

      

      

        
        
        

          A lease lasts 15 minutes regardless and is renewed while work continues, so a revocation lands within
          one lease period rather than at the end of this.
        

      

    


    
    

      

        
        
        

          Comma-separated owner/repo globs; * does not cross the slash, so
          acme/* covers acme/widgets only. Use * alone to allow every
          repository — which is also the only case where a bare GITHUB_TOKEN is exported.
          Narrower grants are delivered as a git credential helper that releases the token per-repository.
        

      

      

        
        
        

          Enforced at cloop's own GitHub call sites. GitHub has no API to narrow an already-issued PAT, so this
          constrains what cloop will do with the token — not what the token is capable of. Mint the PAT
          with the narrowest scopes GitHub offers as well.
        

      

    


    
    

      

        

          
          
        

        

          
          
        

      

      

        At least one of the two is required. The delivered kubeconfig is rewritten to contain only the
        allowed contexts with an allowed namespace pinned on each, so this is enforced by construction rather
        than by convention. Verb-level restriction is not cloop's to give: which verbs the kubeconfig's user may
        use is decided by the cluster's own RBAC, so bind that user to a Role that permits only what this grant
        is for.
      

    


    
    

      

        
        
        

          *.example.com matches subdomains only, not the apex — list the bare domain
          separately if you mean both.
        

      

      

        

          
          
        

        

          
          
        

      

      

        

          
          
        

        

          
          
        

      

      

        
        
        

          The only way to reach a private address: cloop blocks loopback, private, and link-local destinations
          unless a prefix here covers them. Writing 169.254.169.254/32 out in full is deliberate
          — "let this sandbox reach the metadata service" should not be a checkbox.
        

      

    


    
    

      

        
        
        

          The delivered docker config is filtered to these registries, so credentials for the others never
          reach the workload.
        

      

    


    
    

      

        
        
        

          Leave empty to deliver every key the secret holds — safe here because an env secret's own keys
          are its scope, unlike the other kinds where an empty list is rejected.
        

      

    


    
    

      

        
        
        

          This kind carries its allowlist to the executor, whose network policy is the enforcement
          point. For an allowlist cloop itself enforces, use Internet egress above instead.
